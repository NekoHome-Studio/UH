## R1 §6.3.1 会话与消息 —— 补响应定义

在"发送消息请求体"之后追加：

> 同步返回 202 Accepted，data 携带任务句柄：task_id（uh_task_ 前缀）、stream_url（wss://<host>/api/v1/stream?task_id=<id>；M0 过渡可为 SSE https 端点，客户端按 scheme 区分）、trace_id。响应包裹遵循 §6.2；失败错误码见 docs/contracts/errors.md。完整定义见 docs/contracts/task-flow.md §1。

## R2 §6.3.2 任务与执行过程 —— confirm 端点 + seq 对齐

R2a 端点表追加一行：

> POST /tasks/{id}/confirm —— 高危工具确认（confirmation_token + decision），token 一次性防重放；CLI / REST / Web 共用（M1-8）。

R2b steps 示例后追加：

> steps[].seq 与该步骤 step.started 事件的 event_id 对齐；步骤项可附 finished_event_id。事件流超窗回退时，steps 与终态事件可合并重建 UI（见 events.md §7）。

## R3 §6.4 WebSocket —— 事件表 8→18 + 回放语义

R3a 事件表整体替换为 18 事件（完整触发与载荷见 docs/contracts/events.md §3/§4）：

| 事件 | 触发时机 | 载荷摘要 |
|---|---|---|
| task.created | 路由判定完成 | session_id, mode |
| task.finished | 任务完成 | final_result, duration_ms |
| task.failed | 任务失败 | error |
| task.cancelled | 取消/确认拒绝/超时 | reason, error?, completed_steps |
| task.resumed | Checkpoint 恢复 | checkpoint_id, skipped_steps |
| step.started | 能力节点开始 | step_id, module, name |
| step.finished | 节点结束 | step_id, module, status, duration_ms |
| step.failed | 节点失败 | step_id, module, error |
| delta | LLM 流式输出 | text, index |
| tool.call | 工具调用前 | call_id, tool_name, args_summary, risk_level |
| tool.result | 工具返回后 | call_id, status, truncated, content_preview |
| task.confirmation_required | 高危等待确认 | call_id, tool_name, risk_level, summary, token, expires_at |
| task.confirmation_resolved | 确认裁决 | call_id, decision, resolved_by |
| task.yielded | CUA 让位（预留） | reason |
| task.degraded | 能力降级 | reason_code, module |
| safety.check_started | 安全检查开始 | check_id, check_type, target |
| safety.check_finished | 安全检查结束 | check_id, result, duration_ms |
| safety.denied | 安全拦截 | check_id, reason, action_taken |

R3b 载荷隐私收紧：tool.call 的 args 改为 args_summary（脱敏）；tool.result 的 content 改为 content_preview（脱敏 ≤2KB）+ truncated；完整参数与返回不进事件流（§9.7/§9.8）。

R3c 断线语义段替换为：

> 所有服务端事件统一信封 event_id/event/version/task_id/trace_id/ts/payload（span_id 可选）。event_id 任务内单调递增无空洞；重连带 after_event_id 重放（last_event_id 为兼容别名，deprecated_in v0.1.0，v0.2.0 移除）。终态事件（finished/failed/cancelled）必送达：重连时任务已终态则直推终态，不重放中间事件。回放窗口默认 5 分钟，超窗发 replay_unavailable 并 close 4408，客户端回退 /tasks/{id}/steps 全量。关闭码：4401 未认证 / 4403 无权订阅（UH-USR-1002）/ 4404 任务不存在 / 4408 超窗 / 1000 终态正常关闭。

## R4 §6.6 模块间通信协议 —— 信封 event_id + 映射

R4a 统一消息信封追加字段：

> "event_id": 1024  // bus_seq，总线内单调递增；外部 WS 事件经 span_id 关联内部 span，审计反查（§9.8）

R4b 约定区追加：

> 内部事件 → 外部 WS 事件映射以 docs/contracts/events.md §6 为唯一事实源；外部事件必须有内部来源，内部可多于外部（审计粒度）。新增内部事件（capability.finished、llm.delta、mcp.tool.call/result、tool.confirm.resolved、kernel.task.*、safety.*）随 M1-1 登记。事件命名 2/3 段不一致（capability.invoked 等两段 vs 三段约定）由 M1-1 冻结时裁决。

## R5 §9.8 审计与溯源 —— 关联字段

溯源链段追加：

> 审计事件除 trace_id 外携带 task_id 与内部 event_id（bus_seq）；外部 WS 事件信封含 span_id，可实现"审计事件 → 内部 span → UI 事件流"三级反查。
