## R1 §5.2 插件清单 —— 示例与校验规则

R1a 示例整体替换为（补 risk_level / network.allow_hosts / memory_limit_mb / dependencies）：

```yaml
name: web-search
version: 1.0.0
type: tool
entry: main.py
description: "调用外部搜索引擎获取网页摘要"
author: your-name
license: MIT

# 工具风险分级（tool 必填，缺失拒绝加载；§9.6）
risk_level: read-only   # read-only / write-scoped / write-host / irreversible

permissions:
  - network.outbound
  - fs.sandbox.read

# 出网白名单（声明 network.outbound 时必填；与全局配置取交集）
network:
  allow_hosts:
    - api.bing.com

config:
  timeout_ms: 5000
  rate_limit: 10
  memory_limit_mb: 256

# 可选：声明依赖（load 阶段检查就绪，§5.3）
# dependencies:
#   - name: some-plugin
#     version: "^1.0.0"
```

R1b "校验规则"追加三条：

> - tool 插件缺失 risk_level 拒绝加载。
> - permissions 含 network.outbound 时，必须声明 network.allow_hosts（至少 1 项）。
> - manifest 按 type 经 docs/contracts/manifest/<type>.schema.json 校验（统一入口 manifest.schema.json），type 与加载器不一致拒绝加载。

R1c 权限枚举表（新增，5 项）：

| 权限 | 含义 | 备注 |
|---|---|---|
| network.outbound | 允许出网 | 须配套 network.allow_hosts |
| fs.sandbox.read | 沙箱目录只读 | |
| fs.sandbox.write | 沙箱目录写入 | P0-2 新增，支撑 §9.6 write-scoped |
| fs.host.read | 跨目录读宿主 | §5.5 |
| memory.short_term.read | 读取短期记忆 | |

枚举扩展需契约修订（只增不改）。

R1d 类型差异说明（新增）：theme 无 entry（§5.7 仅需 YAML，无需编码）；hook 的 config.events 必填（至少 1 项）；tool/capability/hook 的 config 必含 timeout_ms 与 memory_limit_mb。

## R2 §5.3 install 行 —— 签名策略统一

原文：install：包体校验 SHA-256；工具/能力/钩子插件要求签名（主题插件可免签）。

替换为：install：包体校验 SHA-256；签名策略以安全配置（§9.10）为准：默认全部类型要求签名，theme 可经 plugin.signature_exceptions 配置豁免，例外清单默认为空（即全签）。

## R4 §9.6 工具调用安全 —— 分级落 manifest

工具分级表下追加：

> risk_level 为 tool 插件 manifest 必填字段（见 §5.2 / manifest schema），缺失拒绝加载；确认策略由 §9.10 confirm_levels 决定。

"调用约束"出网白名单条追加：

> allow_hosts 在 manifest.network.allow_hosts 声明，与全局 tool.network_allow_hosts 取交集，默认拒绝。

## R5 §9.10 安全配置参考 —— plugin 段

原文：signature_required: true（无例外机制，与 §5.3 矛盾）。

替换为（plugin 段完整）：

```yaml
plugin:
  sandbox:
    enforce: true
    default_network: deny
    seccomp: whitelist
    run_as_non_root: true
  signature_required: true          # 默认全签
  signature_exceptions: []          # 可配置例外类型，如 [theme]；默认空 = 全签
  permission_prompt: true           # 安装时逐项确认权限
```

tool 段 network_allow_hosts 追加注释：全局上限，与 manifest.network.allow_hosts 取交集。

## R6 新发现的冲突 / 缺口（登记，交后续任务裁决）

1. 事件命名二义：§6.6 约定 域.对象.动作（三段），但 §5.4 标准事件中 capability.invoked / capability.failed / memory.write 为两段。P0-2 hook schema 兼容 2~3 段；M1-1 冻结内部协议时统一（改名需新事件名 + 旧名 deprecated，遵循只增不改）。
2. 宿主写权限缺口：§9.6 write-host 含"写宿主文件"，但权限枚举仅有 fs.host.read。v0.1.0 暂以 write-host 人工确认流程兜底；是否新增 fs.host.write 由 M2 启动前契约修订裁决。
3. 主题 assets 声明（MIME / 大小 / 来源）留待 M2-4，本 schema 不含 assets 字段。
