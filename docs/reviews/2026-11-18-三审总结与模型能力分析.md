- 立场：按证据评判，承认实现方（DSH）修复仍有残留缺陷，不偏袒

## 一、三审总结

### 1.1 三家 verdict 分歧
| 模型 | 结论 | 新发现 | 风格 |
|---|---|---|---|
| GPT-6-Codex | **不通过** | 6 P1 + 3 P2 | 最严，边缘正确性最 thorough |
| DeepSeek-V4-Flash | **有条件通过**（4 条件） | 10 项（N1-N10，多 P2/P3） | 最严谨，方法论+诚实+严重度校准 |
| Hunyuan-Hy | **通过（有条件）** | 6 非阻塞残留 | 最广（9 项+配置矩阵），但本轮漏 P1 |

**分歧本质是严重度判定 + 探测深度**：GPT-6 把 Chroma guard 绕过/resume-cancel/session 存在性/steps 全量判为 P1 阻断；DeepSeek 把 Chroma guard 判 P2（默认 local 后端不触发，目标部署才暴露）；Hunyuan 未深探这些边缘路径故判通过。**取交集结论：M1 非无条件生产可用，存在真实 P1 残留，须修后再验。**

### 1.2 三家共识（高置信）
- 门禁 142 + full 8/8 **可复现**（但 DeepSeek/GPT-6 都指出 test_reset_cleans_logs 偶发 flaky）。
- 二审阻塞/高危项（鉴权别名/默认豁免、RPC fail-closed、风险降级、Host 注入、Cookie 泄漏、dev 门禁、L3 override、LocalVectorStore guard）**真实关闭**，无新可利用鉴权绕过/越权执行高危。
- **Chroma/LlamaIndex 后端绕过 StorageGuard**（GPT-6 P1-2 / DeepSeek N1）——目标部署形态下存储隔离静默失效，brief 点名项。
- **stream_url 相对路径 vs 契约 wss://**（GPT-6 P1-1 / DeepSeek N2）——外部 SDK 句柄形状问题。
- **/steps 非全量载体**（GPT-6 P1-5 / DeepSeek N4/R8）——读 5min 裁剪缓冲，>5min 任务超窗回退丢早期步骤。

### 1.3 残留真实问题（合并去重，按优先级）
**P1（修后再验）：**
| 问题 | 发现者 | 说明 |
|---|---|---|
| Chroma/LlamaIndex 后端绕 StorageGuard | GPT-6/DeepSeek | add/query 不调 _guard_access；构造跳过 super().__init__ 连 _guard 属性都没有（AttributeError 隐患）；RetrievalService chroma/llamaindex 分支不传 guard |
| resume 后 cancel 失效 | GPT-6 P1-4 | _resume_workflow 新 runner 未写回 task[_runner]，cancel 只取消旧 runner |
| fail-closed 缺 tool.result + span_id | GPT-6 P1-3 | 无 confirm 分支只发 mcp.tool.call 未发 result(denied)，tool.call→result 配对断；bus 桥丢 env.span_id；确认审计无内部 span/event_id |
| 不存在 session 仍 202 | GPT-6 P1-6 | 无 session 注册表/存在性校验，契约要求 USR-1003 |
| /steps 全量语义 + duration_ms null | GPT-6 P1-5/DeepSeek N4 | 超窗丢步骤；运行中 step duration_ms=null 不符 openapi integer |
| stream_url 契约对齐 | GPT-6 P1-1/DeepSeek N2 | 相对路径或 UH_PUBLIC_BASE_URL=https 不转 wss；与 task-flow §1 二选一对齐 |

**P2/P3（条件/登记）：**
- 测试存储未隔离 + test_reset_cleans_logs flaky（DeepSeek N5/GPT-6 P2-3）——conftest 只设 UH_DEV_MODE 未隔离存储，pytest 写真实 .uh/（348 条）；门禁可信度被偶发红侵蚀。
- 幂等锁表无 TTL/容量回收（GPT-6 P2-1）——idempotency_locks 单调增长。
- UI 确认失败后按钮 disabled 不恢复（GPT-6 P2-2）。
- 终态 resume 404/409 顺序（Hunyuan/DeepSeek N3）——无 checkpoint chat 任务 resume 得 404 非 409。
- 事件发射器 15/18（DeepSeek N6）——safety.*/task.yielded 无发射点。
- 共享 token 归属退化 token-only（DeepSeek N7，已知设计局限）。
- CI 未跑 --full（DeepSeek N8）；long_term_memory 未接 guard（N9）；/docs 鉴权模式 401（N10）；dev token 前 6 位（Hunyuan）；aria-live（Hunyuan）。

### 1.4 诚实结论
五轮修复闭合了二审全部阻塞/高危，但**三审证明修复仍留 P1 残留**（尤其 Chroma guard、resume-cancel、session 存在性、fail-closed 事件闭合）。M1 **非无条件生产可用**。GPT-6 的「不通过」成立；DeepSeek 的 4 条件 + Hunyuan 的残留是同一批问题的不同严重度表述。**须修 P1 后再做第四轮验收**，而非宣告通过。

## 二、各模型能力分析（三审，含跨轮趋势）

### 2.1 三审评分（5 分制）
| 维度 | GPT-6 | DeepSeek-V4-Flash | Hunyuan-Hy |
|---|---|---|---|
| 边缘正确性发现力 | **5** | 4.5 | 3 |
| 验证严谨/可复现 | 4 | **5** | 4 |
| 诚实/副作用记录 | 4 | **5** | 4.5 |
| 严重度校准 | 4 | **5** | 3（偏乐观） |
| 生产路径广度 | 4 | 4.5 | **5** |
| 契约精度 | 4.5 | **5** | 4 |

### 2.2 GPT-6-Codex（本轮正确性最狠）
- 6 P1 含三个独家：resume 后 cancel 失效、fail-closed 缺 tool.result、不存在 session 仍 202——另两家都漏。
- 强：专挖修复路径的功能正确性洞，verdict 最严（不通过），不被「门禁绿」迷惑。
- 弱：广度/配置矩阵不及 Hunyuan；严重度全判 P1 略严（Chroma 默认 local 不触发）。
- 跨轮：一审精炼→二审稳定→**三审正确性第一**。说明 GPT-6 在「找修复引入的功能 bug」上本轮最强。

### 2.3 DeepSeek-V4-Flash（方法论与诚实标杆）
- 8 次 pytest 抓 flaky（7 绿 1 红）、63 探针（31+21+11）、诚实记录测试污染（.uh/ 348 条）+ 不写「无条件 142」。
- 10 项发现严重度校准精准（Chroma P2 因默认 local 不触发；4 条件清晰）；指出 Chroma 构造跳过 super().__init__ 的 AttributeError 隐患（比 GPT-6 更深一层）。
- 强：验证方法论 + 学术诚实 + 严重度校准 + 契约精度，四项第一。
- 弱：独家功能 bug 不及 GPT-6（resume-cancel/session 存在性未抓）。
- 跨轮：一审代码深→二审验证严→**三审方法论+诚实+校准第一**，稳定高质量。

### 2.4 Tencent Hunyuan-Hy（本轮偏乐观）
- 9 项生产路径 + 鉴权配置矩阵最广，探针隔离规范；但**漏了 GPT-6/DeepSeek 抓到的多个 P1**（Chroma guard、resume-cancel、session 存在性、steps 全量）。
- verdict「通过（有条件）」相对另两家偏乐观——若单采 Hunyuan 会过早关闭 M1。
- 强：生产路径广度 + 配置矩阵 + 探针纪律。
- 弱：本轮边缘正确性探测不足，严重度偏乐观。
- 跨轮：一审安全广→二审新发现多→**三审相对最弱**（漏 P1）。说明 Hunyuan 强项在安全攻击链/广度，本轮正确性深探不足。

### 2.5 跨轮趋势与综合判断
1. **无稳定排名**：一审 DeepSeek 代码最深、二审 Hunyuan 新发现最多、三审 GPT-6 正确性最狠。模型能力高度任务/轮次依赖。
2. **本轮 GPT-6 正确性第一 / DeepSeek 严谨诚实第一 / Hunyuan 广度第一但偏乐观**。
3. **多模型交叉的价值被三审充分证明**：Hunyuan 单独会误判通过，GPT-6+DeepSeek 揪出真实 P1。任何单一模型都不足以验收——交叉去伪存真。
4. **对实现方的镜鉴**：修复仍留 P1（Chroma guard/resume-cancel/session/fail-closed 闭合），「门禁绿」≠「生产可用」；测试本身污染运行态 + flaky 侵蚀门禁可信度，须先治测试卫生。
