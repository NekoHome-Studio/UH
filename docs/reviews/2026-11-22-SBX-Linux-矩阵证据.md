## 三、本轮修复的三个真 bug（Linux 首次实跑暴露）

### F-L1 沙箱内找不到解释器（阻断级）
- **现象**：`bwrap: execvp /home/a/uh/.venv/bin/python: No such file or directory`，所有 tool 插件 rc=1 秒退。
- **根因**：bwrap 只 ro-bind `/usr /bin /lib /lib64`，**venv/自定义解释器不在其中**。
- **修复**：`kernel/sandbox.py` tool 分支增解释器挂载——挂 `exe.parent.parent`（venv 根），
  并 **resolve 符号链接**后把真实解释器目录一并挂入（uv 装的 CPython 在 `~/.local/share/uv/...`）。
- **验证**：修复后 `RC=0 STDOUT=HELLO_FROM_SANDBOX`。

### F-L2 Linux 无内存限额（SBX-04 缺口）
- **现象**：`memory_limit_mb=64` 但分配 1.2GB 仍 rc=0 正常退出，限额未生效。
- **根因**：内存限额只在 Windows Job Object 实现，Linux 分支缺失。
- **修复**：Linux 用 `ulimit -v <KB>` 包装入口命令（`/bin/sh -c 'ulimit -v N; exec ...'`）。
- **验证**：**MEM_LIMIT_HIT**。

### F-L3 wait() 超时不 kill（SBX-03 缺口）
- **现象**：`SandboxProcess.wait(timeout_s=N)` 超时仅透传 `subprocess.TimeoutExpired`，进程仍在跑。
- **修复**：捕获后 `terminate()` + 等待回收，抛 **UH-CAP-5021**（与 `run()` 口径一致）。
- **注**：`runner.run()` 本就按 `manifest.timeout_ms` 正确限时（1.21s 实测），
  `launch()+wait()` 手动路径此前缺保护，现补齐。

## 四、与 Windows 对比
| 维度 | Windows | **Linux（本次）** |
|---|---|---|
| 后端 | Job Object | **bwrap** |
| degraded | **True**（FS/网络靠 SDK 协作） | **False**（内核级真隔离） |
| FS 隔离 | SDK 行为级拦截 | **ro-bind + bind 挂载边界** |
| 网络隔离 | SDK allow_hosts | **unshare-net 真断网** |
| PID 隔离 | 无 | **unshare-pid（PID=2）** |
| 内存限额 | Job per-process | **ulimit -v** |
| 超时 kill | Job CPU 时间 | **墙钟 timeout_ms 精准** |

> **结论**：Linux 提供比 Windows 更强的隔离保证。生产部署应优先 Linux。

## 六、剩余登记
- **macOS SBX 矩阵**：无 macOS 主机，`sandbox-exec` 分支未实测，继续登记。
- **cgroup v2 资源控制**：Kylin 是 cgroup v1，用 ulimit 替代；cgroup v2 环境可加 Job 级总量限制。
- **多 ID userns**：无 root 装不了 newuidmap，当前单 ID 映射（不影响隔离有效性）。

### SBX-07 enforce 实机拦截验证
```
mount -t tmpfs none /mnt  → rc=1（操作被拒）
ptrace(0,0,0,0)           → rc=-1（操作被拒）
```
bwrap `--seccomp <fd>` 加载 libseccomp 导出的 BPF（`kernel/linux_sandbox.py::seccomp_filter`），`UH_SANDBOX_SECCOMP=enforce` 下 default-deny 生效。

### 实现确认
- `kernel/linux_sandbox.py::seccomp_filter`：libseccomp 编译 default-deny + 白名单 → `seccomp_export_bpf` 到临时 fd
- `kernel/sandbox.py:143-150`：bwrap `--seccomp <fd>` + `pass_fds` 注入；audit/disabled 模式记录 `plugin.sandbox.seccomp_debug`
- `build_plan` 看不到 seccomp 标记属**设计正确**（launch 时才注入，供 pass_fds 传递）

### cgroup 继承 SKIPPED 说明
测试需 `UH_SANDBOX_CGROUP_ROOT` 指向已委派的 cgroup v2 目录；Kylin 是 cgroup v1 且无 root 无法建委派层级。已在 M3-7 交付 `kernel/linux_sandbox.py::PluginCgroup`（v2 v1 双支持），待有 root 的 Linux 环境补采。

### 结论
**SBX-07/08/09（M3 必过三项）在 Kylin Linux 实机全部通过**，连同此前 SBX-01~05 + ISOLATION + NET + CRED_STRIP，**Linux 平台矩阵除 cgroup 继承（SKIPPED，需 root）外全部闭合**。
