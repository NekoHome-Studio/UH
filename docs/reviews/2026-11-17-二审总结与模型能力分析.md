## 一、二审总结

### 1.1 三家共识结论
**原高危多数真修复，门禁已真实生效（129/129，verify-all full 8/8，CI 补 pytest），但修复本身引入或留下可绕过缺口——M1 暂不能宣告生产验收通过。**

### 1.2 确认真修复（三家复核一致）
- 上轮 5×P0 全修（DeepSeek 逐条可复现）：steps 端点 / resume 终态 guard 409 / WS auth 实时投递 / 确认 TTL 自动超时 / RPC 任务级 deadline。
- WS 空 token 绕过、路径穿越（主入口）、CLI 中文编码、CI 不跑 Python 门禁——实修。
- 错误码语义按 ADR-003 合规拆解（只增 UH-CAP-4004，CAP-4003 原义不动）。
- **bus→task 事件桥**被 DeepSeek 评为最有价值修复：高危工具任务完整序列 task.created→tool.call→confirmation_required→confirmation_resolved→tool.result→task.finished，event_id 连续无空洞、顺序合 §5.4、脱敏未破。

### 1.3 二审新发现（修复引入/遗留，按严重性合并）

**阻塞级（三家收敛或独家高危）：**
| 问题 | 发现者 | 性质 |
|---|---|---|

| REST 鉴权默认豁免：UH_LOCAL_MODE 默认 1，单设 UH_AUTH_REQUIRED=1 无效（REST 全开 WS 却开鉴权） | Hunyuan N1 | 我引入（REST/WS 默认值不一致） |
| MCP RPC 通道绕确认门：register_capabilities handler 调 call_tool 不传 confirm，RPC 执行高危工具不确认 | Hunyuan N3 | 我引入（确认门只在 inline 路径） |

**高危：**
| 问题 | 发现者 |
|---|---|

**契约/治理/质量（中低）：**
- 401 早返回缺 meta.trace_id（DeepSeek R2 / GPT-6）；steps/cancel 响应形状不符 openapi + 409 未登记（DeepSeek R3 / GPT-6）。
- StorageGuard.authorize 恒真空操作（DeepSeek P1-8 / Hunyuan N7 自我修正表述）——我「形式接线」。
- 错误码计数未回写（errors.md 标题 13 实 14，DeepSeek R4）；ADR-003 插件覆盖承诺未实装 + event_mapping 兜底仍 4003 + 4004 retryable 不一致（DeepSeek R11 / Hunyuan N10）。
- 取消不闭合 step / 取消后 token 仍可批准 / confirm_timeout 跨轮不重置（GPT-6 / Hunyuan N9 / DeepSeek R7）。
- 模块不可用误标超时 5021（GPT-6）；L3 override 绕过明文入库（GPT-6 P2）；幂等并发竞态（三家）。
- 记忆 scope 默认 global 仍跨会话 + context 可覆盖管理员 session（Hunyuan N12）；deadline 分层回归（Hunyuan N11）。
- UI 确认弹窗/重连/超窗回退渲染/degraded 徽标全缺失，4401 误报 KRN-5001（Hunyuan N14）。
- 旧问题未动：limit=0 返回全部 / checkpoint_id 重生成 / PG 静默 SQLite / 嵌套 trace clear() / MCP stderr / 坏 L2 记录崩溃召回（Hunyuan N13）。

### 1.4 诚实结论
测试数字变漂亮（110→129）≠ 生产可用。**我的修复引入了多个可绕过缺口**（别名绕过、默认豁免、RPC 确认绕过、Host 注入、Cookie 泄漏、形式接线），二审正确拦截。M1 须按「生产链路可观测」口径再修再验，而非再看 fixture。

### 2.2 GPT-6-Codex（精炼精准的稳定输出）
- 二审 1 P0 + 8 P1 + 4 P2，全带 file:line + 实测；**风险级降级绕过确认门**是独家 P0。
- 强：表述干净、直击要害、无冗余；取消后 token 仍可批准、模块不可用误标 5021、L3 override 绕过都抓得准。
- 弱：广度不及另两家（未抓 Host 注入/Cookie 泄漏/RPC 确认绕过/UI 缺失）；治理/旧账覆盖少。
- 一审→二审：稳定，深度略增，仍是「快速精准复核」首选。

### 2.3 DeepSeek-V4-Flash（验证方法论与契约精度标杆）
- 二审 4 P1 + 8 P2，**上轮 5×P0 逐条可复现验收矩阵**是独有方法论；R1 鉴权别名绕过实测清空数据。
- 强：验证严谨（门禁亲复现 + 探针 + 复现命令）、契约精度（openapi 形状/409 登记/计数回写/ADR 文档 vs 实现）、**学术诚实**（专节记录探针误清测试数据的副作用 + 不可恢复 + 教训）。
- 弱：新缺陷绝对数量不及 Hunyuan（未抓 Host 注入/Cookie 泄漏/RPC 确认绕过）；安全攻击链想象力略逊。
- 一审→二审：从「代码逻辑最深」进化为「验证最严谨 + 契约最准」，Flask 档持续超预期。

### 2.4 Tencent Hunyuan-Hy（最广最狠的安全审计）
- 二审 3 阻塞 + 3 高危 + 8 中低，**新缺陷最多**；独家 N3 RPC 确认绕过 / N4 Host 注入 / N5 Cookie 泄漏 / N8 换 token 不重校归属 / N14 UI 全缺失。
- 强：安全攻击链想象力最强（三个独家高危皆可直接利用）、覆盖最广（UI/旧账/治理/配置一致性）、**自我修正**（N7 纠正上轮「无调用点」为「恒真空操作」）。
- 弱：篇幅最长、精炼度最低；契约字段级精度略逊 DeepSeek。
- 一审→二审：从「安全+治理最广」升级为「综合发现力第一」，二审拉开差距。

### 2.5 综合判断
1. **二审 Hunyuan 综合第一**（新缺陷最多 + 三个独家可利用高危 + 最广覆盖 + 自我修正）；DeepSeek 验证严谨与契约精度第一；GPT-6 精炼稳定。
2. **能力高度任务依赖**：安全攻击链找 Hunyuan，契约/验证找 DeepSeek，快速复核找 GPT-6。一审「DeepSeek 代码最深」在二审被 Hunyuan 的广度+安全深度超越——说明单轮排名不稳定，多轮多模型交叉才可靠。
3. **三家共同价值**：都独立实测、都拒绝盖章、都抓到实现方（DSH）自审发现的缺口——**独立多模型审查显著优于实现方自审**，这正是用户坚持「二审不是你」的价值。
4. **对编排者的镜鉴**：我的修复引入回归（前缀鉴权/默认值/Host 拼接/Cookie 缓存/形式接线），说明「修一个洞可能开另一个洞」，修复必须配绕过路径回归测试，而非只测修复函数本身。

## 三、合并修复优先级（供下一轮）
1. 立即：REST 鉴权默认值与 WS 对齐 + 保护所有别名（或删别名）；MCP RPC 确认门下沉强制；风险级以工具声明为准（调用方不可降级）；移除 Host 头拼接用可信配置。
2. 高：幂等缓存剔 Set-Cookie + 绑调用者 + in-flight 锁；dev_route 补门禁 + dev 默认关；WS 换 token 重校归属；REST 资源归属校验。
3. 中：StorageGuard 真实目标命名空间校验；401 meta.trace_id + steps/cancel openapi 形状 + 409 登记；计数回写；清 confirm_timeout + 取消闭合 step + 撤销 token；ADR-003 覆盖实装 + retryable 对齐；记忆 scope 默认 session。
4. 低：UI 确认/重连/回退/徽标；limit=0 / checkpoint_id / PG 告警 / trace reset / MCP stderr / 坏 L2 隔离 / 日志脱敏。

## 四、验收口径建议
以「生产链路可观测」逐条签核：带鉴权跑 WS 实时流 + 工具确认（inline 与 RPC 两路）+ 取消 + 超窗回退 + 跨客户端隔离，每条配绕过路径回归。fixture 全绿不再作为验收依据。
