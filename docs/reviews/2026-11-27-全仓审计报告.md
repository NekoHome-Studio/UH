## 必须修复

### 1. 会话消息和短期记忆端点缺少会话属主校验（P1）

**位置：** [`kernel/main.py` 短期记忆读取](../../kernel/main.py#L689-L693)、[`kernel/main.py` 会话消息读取](../../kernel/main.py#L695-L713)

**触发条件：** 在严格认证配置中，攻击者持有全局 Bearer Token 并获知另一个会话 ID，即可请求相应读取端点。全局 token 仅证明调用者可访问服务，不证明其拥有该会话。

**影响：** 可读取其他会话的短期记忆或对话消息。实际探针创建会话、清除客户端会话 cookie 后，仍以全局 token 请求 `GET /api/v1/sessions/{session_id}/messages`，返回 HTTP 200 并包含夹具中的私有标记。

**最小修复：** 两个端点均做会话存在性检查，并调用与会话详情/消息写入相同的属主校验；补充“合法全局 token、错误或缺失 client identity”的跨会话回归用例。

### 2. 首次 JSONL 追加会破坏旧 JSON 数组存储（P1）

**位置：** [`kernel/retrieval.py` 加载器](../../kernel/retrieval.py#L136-L168)、[`kernel/retrieval.py` 追加写入](../../kernel/retrieval.py#L177-L194)；[`kernel/long_term_memory.py` 加载器](../../kernel/long_term_memory.py#L186-L221)、[`kernel/long_term_memory.py` 追加写入](../../kernel/long_term_memory.py#L228-L236)

**触发条件：** 用户已有旧版 JSON 数组格式的存储文件，升级后首次写入会在数组文本末尾直接追加 JSONL 记录。重启时加载器因文件以 `[` 开头而尝试整体解析 JSON；数组后多出的对象行使解析失败，条目列表被置空。

**影响：** 检索文档和长期记忆在升级后的下一次读取中不可见。探针分别从旧数组文件加载、追加一条记录、重新构造存储对象，两个存储重载结果均为空。

**最小修复：** 首次追加前检测旧格式并迁移成 JSONL；迁移采用临时文件和原子替换，之后再追加。为两种存储分别增加“旧数组升级、追加、重启、旧记录仍可读”的回归测试。

### 3. 同 ID 替换文档后，倒排索引未失效（P1）

**位置：** [`kernel/retrieval.py` 文档替换](../../kernel/retrieval.py#L187-L205)、[`kernel/retrieval.py` 候选检索](../../kernel/retrieval.py#L207-L230)

**触发条件：** 用同一个 `document_id` 更新文本，导致旧文档被移除、新文档追加，但文档总数不变。`query()` 仅以文档数量判断是否重建倒排索引，因此沿用旧 token 到位置的映射。

**影响：** 新文本无法被正确召回，或者旧映射将候选位置指向另一篇文档。确定性探针中，更新前先查询 `q` 建立索引，再将文档 A 更新为包含 `q` 的新文本；旧索引返回空结果，新建存储的结果则返回 A。

**最小修复：** 文档变更时同步维护索引，或设置失效标记并在下一次查询重建；增加同数量 upsert 后查询新词与删除旧词的测试。

## 应修复

### 4. 编排降级分支把用户输入当成最终回答和 assistant 记忆（P2）

**位置：** [`kernel/tasks.py` 编排降级分支](../../kernel/tasks.py#L444-L459)、[`ui/state-machine.js` routing 转移](../../ui/state-machine.js#L29-L33)

**触发条件：** `orchestration.run` 返回降级结果，内核使用普通 LLM 流式回退。

**问题与影响：** delta 流完后，`task.finished.final_result.content` 仍写入原始用户 `content`，assistant 长期记忆也存储用户输入，而不是流式生成的回答。该分支还没有发送 `step.started`；根据 UI 状态机，`task.degraded` 不会迁移状态，界面会一直停在 `routing` 直到终态。

**最小修复：** 收集 delta 形成 `answer`，将其用于终态与 assistant 记忆；降级生成前后发出配对步骤事件。补充断言最终结果、assistant 记忆和 UI 状态均与实际回答一致。

### 5. 长期记忆追加失败被吞掉，调用方仍收到成功（P2）

**位置：** [`kernel/long_term_memory.py` `_append`](../../kernel/long_term_memory.py#L228-L236)

**触发条件：** 目标目录只读、磁盘写入失败或其他 `OSError`。

**问题与影响：** `_append()` 捕获异常后直接返回；`write()` 仍返回已创建的 entry。数据只留在当前进程状态，重启后消失，调用者也收不到失败信号。

**最小修复：** 持久化失败应向上抛出，或返回明确的持久化状态；不要把失败当作成功。增加对 append 写入失败的测试。
