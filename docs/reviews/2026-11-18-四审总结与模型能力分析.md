### 1.2 P0 阻断（必须先处置）
**P0-1 鉴权主令牌泄露（三家共识，DSH 引入）：**
- 明文 token 随 d23d027 提交进 docs/runbooks/环境状态总览.md:55，**已推 origin/main，仓库 public**（DeepSeek 经 GitHub API 确认 private=false）。
- git 历史可检索（git log -S 命中）；服务器 kernel.out.log 97~113 行 token= URL、kernel.err.log WS 握手含完整令牌；WMI 进程命令行明文。
- 违反 AGENTS.md §4 密钥硬规则。单共享 token 模型下，读仓库/日志/进程列表任一方即获完整业务权限。当前无公网映射故公网暂不可利用，**内网穿透即等同无鉴权**。
- 处置：①立即轮换 token（旧失效）②文档改占位符③清 git 历史④清服务器日志⑤启动脚本从 env/凭据管理器读 token 禁入命令行⑥uvicorn access log 脱敏⑦secret 扫描门禁。

**P0-2 跨客户端越权链（Hunyuan 独家，6 步真实复现）：**
- SSE /tasks/{id}/stream 是唯一缺 _task_guard 的任务端点（其余 5 个都有）→ 任何持共享 token 者读他人任务事件流。
- task.confirmation_required payload 带**完整确认令牌** → SSE 旁路了 dev/confirmations 的 [redacted] 脱敏 → 偷令牌。
- owner_matches 持 token 时 client_id 分支恒不执行 → 单共享 token 下所有任务级守卫失效。
- 实测：attacker 读 victim 任务→SSE 偷令牌→confirm rejected→victim 任务被改 cancelled。
- 定性：SSE 缺 guard 是**实现缺口**（非纯设计局限）；确认令牌泄露使高危确认形同虚设。
- 处置：①SSE 补 _task_guard②确认令牌对非归属者脱敏/带外下发③owner_matches 双因子（token+client_id）④per-user principal 或契约明示单用户等价。

### 1.3 P1/P2（修复前不视为生产就绪）
- dev 端点生产可远程关能力（UH_DEV_MODE=1 验收期）→ 生产设 0 + toggle 审计。
- WS 事件风暴（MockLLM 逐字符 delta，单任务 8188 帧）+ 终态缓冲/tasks dict 不回收 → delta 合批 + 终态释放 + 背压。
- 幂等 caller 漂移（send_message set_cookie 改写 caller，同键同 body 重复执行）→ caller 稳定绑定。
- tool 事件 span 溯源未闭合（mcp.tool.call 未生成 span，result 未复用 call span，确认审计无 bus/event/span）→ span 传播 + 审计事件。
- 契约门禁跨机不可复现（服务器 verify-all B2/C fail：js-yaml 路径 + python 解释器）→ verify-all 显式 PYTHON/YAML_PATH。
- UH_RETRIEVAL_ROOT 未配置 D:\uh\data 不存在（按路径索引 100% 失败）→ mkdir + 设 ROOT。
- 明文 HTTP + query token → TLS 反代 + WS 短时票据（HMAC(task_id,exp) TTL60s）。
- CAP-4004 路径越界 retryable=true（必然失败却可重试）→ retryable=false。
- /metrics /docs /openapi.json 免鉴权 → 写进 deploy-hardening 豁免清单。
- server-state.ps1 kernel version 步骤 unicodeescape（D:\uh 进 python -c）→  raw string。

### 1.4 诚实结论
跨机功能层达标（可进 M2 功能开发），但**安全层不能放行**：P0-1 是 DSH 引入的已发生密钥泄露事件，P0-2 是可利用越权链。须先轮换令牌+清仓库日志+SSE 守卫+归属双因子，复跑服务器 pytest+跨机探针，方可签最终通过。
