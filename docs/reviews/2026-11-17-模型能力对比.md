- 依据：docs/reviews/ 下三份署名报告 + Hunyuan 867 行详版（含复现脚本与原始输出）

## 0. 一句话结论

三个模型都具备**真实运行时验证能力**（非纸面审查），都准确、专业、有结构。但能力侧写明显不同：
**DeepSeek-V4-Flash 代码正确性最深，Hunyuan-Hy 安全攻击链与治理最广，GPT-6 最精炼高效**。三者互补，无一家覆盖全部问题。

## 3. 各家独家发现（别家没抓到的）

### DeepSeek-V4-Flash（代码逻辑最深）
- **resume 破坏终态唯一性**：已完成任务 resume 后出现两个终态事件，且 test_orchestration 把缺陷写成断言（测试保护 bug）。
- **RPC 8s deadline < 编排 4 节点预算**：真实 workflow 必被 RPC 层抢先杀掉；mock 毫秒节点使 111 绿灯发现不了。
- **CAP-4003 语义挪用**：LLM 上游错误码被用于 MCP 传输/任意模块异常，前端按域文案会错。
- **18 事件仅 11 个有运行时发射器**：缺 bus→task stream 桥，UI 状态机部分分支是死代码。
- **checkpoint_id 每节点重生成**：upsert 实为 INSERT，按旧 id resume 读旧快照，表线性增长。
- **LangGraph 后端答案可能丢** + **编排降级把用户原话当答案写入记忆**。
- **长期记忆默认跨会话召回**（需契约裁决全局 vs 按会话）。

### Hunyuan-Hy（安全 + 治理最广）
- **WS 鉴权绕过**：未配 token 环境变量时，任意非空 token 直接 authenticated=True（R1 实测）。
- **任意路径索引外泄**：_read_document(path) 无白名单，配合无鉴权 /dev/tool-task 闭合攻击链（R3）。
- **CLI 中文 Windows GBK 解码崩溃**：tasklist 输出解码失败 → stdout=None → TypeError（其环境 110/111）。
- **治理状态漂移**：契约正文仍 needs-review、无人工评审记录、AGENTS/README 停 M0、PROGRESS 自相矛盾、issue 39vs38、tag 计数 4vs「三」。
- **CI 不跑 pytest/verify-all**：触发路径排除 kernel/tests，只跑 Node 契约校验。
- **verify-all 硬编码 python + E 项恒真不可能失败**；无 shutdown 释放；dev_reset flushdb 整库。

### GPT-6-Codex（精炼精准）
- 8 项全部有效且带 file:line + 实测，无冗余；**幂等键未绑请求体**、**非 MCPError 异常任务悬挂**表述最干净。
- 但深度/广度不及另两家：未抓 resume 终态、deadline 分层、WS 空 token 绕过、路径穿越、治理。

## 4. 共同发现（三家都抓到，可信度最高）

- stream_url 仍 SSE（M1-7 应返回 WS 句柄）
- /tasks/{id}/steps 与 /cancel 未实装（4408 回退 404）
- WS 首帧 auth/重订阅后实时事件丢失（queue_task 未重建）
- 确认 TTL 不自动超时（pending_confirmation 永久挂起，resolved_by=timeout 死代码）
- dev/confirmations 无鉴权泄漏确认令牌
- 幂等键未绑 body / 无 TTL/容量

> 这些是**高置信真缺陷**（三家独立收敛），应优先修。

## 5. 客观评判

1. **没有一家全覆盖**：DeepSeek 漏了 WS 空 token 绕过与路径穿越（Hunyuan 抓到）；Hunyuan 漏了 resume 终态/deadline 分层/CAP-4003 挪用（DeepSeek 抓到）；GPT-6 两者都漏但最精炼。
2. **「轻量模型」未必弱**：DeepSeek-V4-Flash（Flash 档）代码审查深度反而超过 GPT-6 旗舰档——能力高度任务依赖，不能只看档位。
3. **Hunyuan 的工程化审计最完整**：复现脚本全文 + 原始输出 + 未覆盖声明（附录 C），证据链可追溯，适合做正式验收审计。
4. **三家都正确**：M1 的「111/111 + 验收✅」是 fixture/单测口径，非生产链路口径；存在可直接利用的安全洞。**编排者（DSH）此前的封板声称过度**，审查结论成立。

## 6. 使用建议（互补编排）
