## 发现（按严重度）

### P1 阻断／发布前应修

#### P1-1 日志脱敏的熵兜底形同虚设：短凭据、非 ASCII、含空白串全部明文泄漏
- **位置**：`kernel/redaction.py:52-61`（`_looks_like_secret`）、`:64-75`（`redact_text`）
- **复现**（`.work/review-probes/probe_redaction2.py`，实跑输出）：

  | 输入 | 长度 | Shannon 熵 | `redact_text` 结果 |
  |---|---|---|---|
  | `xQ7pL2mN9vR4tY8wZ1aB` | 20 | 4.32 | **原样泄漏** |
  | `口令xQ7pL2mN9vR4tY8wZ1aB3cD5eF7g` | 30 | 4.84 | **原样泄漏**（非 ASCII） |
  | `xQ7pL2mN9vR4tY8 xQ7pL2mN9vR4tY8` | 31 | 3.99 | **原样泄漏**（按空白切分后每段 <24） |
  | `xQ7pL2mN9vR4tY8wZ1aB3c\tD5eF7gH9iJ` | 33 | 4.92 | **原样泄漏**（含 tab） |
  | `xQ7pL2mN9vR4tY8wZ1aB3😀cD5eF7gH9iJ` | 33 | 4.92 | **原样泄漏**（emoji） |
  | `xQ7pL2mN9vR4tY8wZ1aB3cD5eF7gH9iJ` | 32 | 4.88 | `*REDACTED*` ✅ |

- **根因**：`len<24 or len>512` 直接返回 False；`any(c.isspace())` 直接返回 False；`re.fullmatch(r"[A-Za-z0-9._~+/=:-]+")` 排除非 ASCII。且 `redact_text` 先按 `re.split(r"(\s+)")` 切分再逐 token 判定，任何含空白的高熵串被拆成短段后必然漏过。
- **影响**：RELEASE.md:26 声称「6 类正则 + Shannon 熵检测」双轨脱敏；SEC-01 声称凭据脱敏。实际常见形态（带空格的口令、中文混入的 token、20 字符短密钥）**全部明文进日志**。日志是长期留存且常被集中收集，泄漏面高于内存态。
- **建议**：把长度下限降到能覆盖真实凭据（如 16），按字符类别计算熵而非整串 `isspace()` 否决，对非 ASCII 用 Unicode 类别判定；对含空白串按「连续非空白片段」分别判定而非丢整串。加上述 6 组回归。

#### P1-2 性能声明的证据链失真：所谓「双端硬件基线」服务端根本没有硬件字段
- **位置**：`kernel/bench.py:191-209`（`fetch_server_baseline`）、`:224-226`；`benchmarks/README.md:24-31`；`RELEASE.md:42`
- **复现**：`benchmarks/*.json` 三个文件的 `server_baseline` 实际内容只有：
  ```
  {"health_status": 200, "kernel_version": "0.1.0", "metrics_families": 174|190}
  ```
  而 `client_baseline` 有 platform/cpu_count/memory_total_gb。`fetch_server_baseline()` 只请求 `/health` 和 `/metrics`，**从不采集服务端 CPU/内存/平台**。
- **影响**：`benchmarks/README.md:30-31` 明写「报告中 client_baseline 与 server_baseline 分列，引用数字时必须以服务端基线为准（无硬件基线的性能数字不可比）」，RELEASE.md:42 宣称「双端硬件基线（数字可比）」——但服务端硬件数据**从未被采集**，该承诺不成立。此外三份随包 JSON 的 P95 是 16065/55776/62635 ms、错误率 1.5%/0%/18%（全部 FAIL），与 R1/RELEASE 宣称的「6.7~7.2s、错误率 0%」是**不同数据集**，仓库内找不到后者的原始 JSON，8~9 倍改善无法从交付物复核。低并发「5 并发 P95≈186ms」同样无原始数据。
- **建议**：要么在服务端 `/health` 暴露硬件信息并让 `fetch_server_baseline` 采集，要么撤回「双端硬件基线/数字可比」表述；把最终 6.7~7.2s 那组原始 JSON 随包提交，否则「改善 8~9 倍」属于不可复核的自报数字。

#### P1-3 门禁只认一个变量名，且 `${VAR:?message}` 可夹带明文凭据过双门禁
- **位置**：`scripts/secret-scan.mjs:9`（`AUTH_TOKEN_PATTERN` 只匹配 `UH_AUTH_TOKEN`）、`verify-compose-exposure.mjs:12,32-38`
- **复现**（`.work/review-probes/probe_gates.mjs` 实跑）：
  - `${UH_AUTH_TOKEN:?placeholdersamplecredentialabc}` 作为环境项：`verifyComposeExposure` 返回 `[]`（PASS），`hasPlainAuthToken()` 返回 `false`（0 命中）。根因：`:?message` 分支被 `ENV_REF` 判为合法引用，且内联凭据扫描前用正则把整个 `${...}` 删除，message 从未被检查。
  - `UH_MEMORY_MASTER_KEY = "supersecretvalue1234567890"`、`UH_LLM_API_KEY: "sk-..."`、小写 `uh_auth_token = "..."`、字符串拼接、`base64.b64decode("...")` 五种写法 `hasPlainAuthToken()` 全部返回 `false`——扫描器只认大写 `UH_AUTH_TOKEN` 且要求 20+ 连续 `[A-Za-z0-9_-]` 立即跟在赋值号后。
- **影响**：RELEASE.md:50 / CHANGELOG:16 声称「密钥扫描门禁：仓库零明文凭据」。实际只要换个变量名或塞进 `${VAR:?...}` 就能携带真实凭据而不触发门禁。`${VAR:?default}` 夹带正是任务书点名的攻击面，已证实。
- **建议**：扩展为「常见凭据变量名 + high-entropy 字面量」双模式，扫描全部 `${VAR:?...}` 与 `${VAR:-...}` 的默认值文本，覆盖 base64/拼接形态。

#### P1-4 K8s J 项可整段绕过：`otel-collector` 被列入白名单却不在加固循环内
- **位置**：`scripts/verify-k8s-manifests.mjs:19,28,180-225`（`workloads = [KERNEL, ...capabilities]`，`otel-collector` 仅在 `resources` 与 `Service` 白名单中，从不进入 podSpec/securityContext/ServiceAccount 校验）；`verify-security-hardening.mjs:9`（M 项 `WORKLOADS` 同样不含 otel-collector）
- **复现**（`.work/review-probes/probe_k8s.mjs` 实跑）：读取真实 `deploy/k8s/*.yaml` 后，仅修改 `otel-collector` Deployment：
  ```js
  spec.hostNetwork = true;
  spec.automountServiceAccountToken = true;
  spec.serviceAccountName = "uh-scaler";   // 挂上唯一的高权限 SA
  spec.containers[0].securityContext = { privileged: true };
  spec.containers[0].ports = [{ containerPort: 4317, hostPort: 4317 }];
  ```
  `verifyK8sManifests(docs)` 返回 `[]`（J 项 PASS）。M 项也不检查该工作负载。**注**：仓库中实际交付的 manifest 是干净的（无上述字段），所以这是「门禁能过但实质违规」的绕过样本，不是已交付配置里的漏洞。
- **影响**：CHANGELOG:47 宣称「最小 RBAC：uh-scaler 仅 deployments/scale 子资源」，但任何被授权编辑 K8s 清单的人（或供应链投毒）可在**不触发任何门禁**的前提下，让一个 privileged + hostNetwork + 宿主端口的容器持有 scaler 凭据，直接打破 NetworkPolicy 与 RBAC 隔离。J/M 两道门同时失守。
- **建议**：把所有 Deployment/StatefulSet（含 otel-collector）纳入同一加固循环；断言非 kernel 工作负载不得使用 `uh-scaler` SA、不得 `hostNetwork`/`hostPort`/`privileged`；M 项 `WORKLOADS` 补齐 otel-collector。
