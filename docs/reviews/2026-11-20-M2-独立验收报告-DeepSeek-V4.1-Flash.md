## 5. 新发现

### P1-1 已安装工具/钩子子进程缺少 `PYTHONPATH`，官方 SDK 插件安装后崩溃循环

- 位置：`kernel/sandbox.py:234`（tool 计划复制 `os.environ`，未注入内核根路径）；`kernel/cli.py:321`（仅 `plugin dev` 设置 `PYTHONPATH`）
- 现象：通过 REST 安装签名 `echo-tool` 返回 `201 active`，随后进程以 `ModuleNotFoundError: No module named 'kernel'` 退出，崩溃 3 次后 `quarantined`。三个官方工具均 `from kernel.plugin_sdk import ...`，同样受影响。
- 复现：把工具包解压到任意目录，`cd` 到包目录执行 `python main.py`，即报 `No module named 'kernel'`；或在临时内核安装签名工具后 `GET /api/v1/plugins` 观察 `quarantined`。
- 影响：M2-1 “已安装工具可用”、M2-3 “签名工具注册与调用”在生产链路上不成立。

### P1-2 已安装插件工具没有生产能力调用路径

- 位置：`kernel/main.py:807`（`dev/tool-task` 固定使用 `retrieval_host`）；`kernel/tasks.py:164`（`host.call_tool` 目标为 retrieval MCP Host）；全仓库无 `rpc.register` 插件工具。
- 现象：安装 `echo-tool` 后调用 `echo`，任务进入 `pending_confirmation` 或失败，从未路由到插件进程。
- 影响：插件“安装成功”只是目录与注册表状态，无法被主链路调用。

### P1-3 内核启动不重激活已安装插件/Hook

- 位置：`kernel/main.py:333-343`（启动钩子仅 `retrieval_host.register_capabilities`）
- 现象：重启后插件状态全部回落为 `installed`；`audit-log` Hook 不再收到事件（审计新增 0 行）。
- 影响：M2-1 “内核启动后插件重激活”、M2-5 “服务重启后 Hook 恢复”不成立；“装/卸插件不重启”只在单次进程生命周期内成立。

### P1-4 插件校验无危险调用静态扫描

- 位置：`kernel/plugins.py:736-745`（`validate` 仅清单 + 签名 + 摘要）
- 现象：含 `socket`、`os.system`、`subprocess.run` 的签名包 `uh plugin validate` 返回 `status=validated`。
- 影响：SBX-02 “出网静态扫描前置”、M2-6 “静态扫描越界/危险调用拒绝”不成立。

### P2-1 沙箱拒绝无审计、错误码未透出

- 位置：`kernel/sandbox.py:62-82`（仅抛异常，无审计写入）
- 现象：SDK 越权返回文本仅中文消息，不含 `UH-KRN-2010`；内核侧无审计记录。
- 影响：SBX-01 “SDK/代理拒绝 + 审计”只完成拒绝部分，事后追溯不足。

### P2-2 激活失败回滚对“立即崩溃”无效

- 位置：`kernel/sandbox.py:151-154`（`activate` 仅在 `sleep(0)` 后检查 `poll()`）
- 现象：`SystemExit(2)` 工具安装返回 201 active，随后崩溃 3 次才隔离；安装阶段未回滚。
- 影响：M2-1 “激活失败回滚”在真实 Windows 进程加载器上不成立。

### P2-3 服务器部署与声明基线不一致

- 证据：§1.2；服务器无 M2 内核文件、`main.py` 哈希不同、148 测试 1 失败、OpenAPI 无主题路由。
- 影响：A（服务器门禁/部署一致性）与 C（跨机链路）无法按 MS-3 口径验收。

## 6. 验收结论与 MS-3 建议

### 结论：**不通过**（按当前证据，MS-3 暂不结项）

理由：
1. 生产链路核心闭环不成立：已安装工具无法导入内核、无调用路径（P1-1/P1-2）。
2. 重启恢复缺失：插件与 Hook 均不重激活（P1-3），与 M2-1/M2-5 验收项直接冲突。
3. 安全矩阵不完整：SBX-01 审计缺失、SBX-02/M2-6 静态扫描缺失（P1-4/P2-1）。
