## 结论

当前不建议判定 M1 完成。基础测试和契约门禁通过，但仍存在影响任务流、事件流、确认安全和幂等语义的问题。

## 发现

### P1：M1-7 返回的 `stream_url` 仍是 SSE

[kernel/main.py:427](../../kernel/main.py:427) 返回 `/api/v1/tasks/{id}/stream`，该路由在 [kernel/main.py:473](../../kernel/main.py:473) 使用 `StreamingResponse` 提供 SSE。M1 要求统一 WebSocket；客户端按返回句柄连接时无法获得 WS 的回放、关闭码和终态语义。

### P1：回放超窗回退接口和取消接口未实现

当前没有 `/api/v1/tasks/{id}/steps` 和 `/api/v1/tasks/{id}/cancel` 路由。WS 返回 4408 后，UI 对 steps 的回退请求会得到 404；契约定义的取消操作也无法执行。

### P1：首帧 `auth` 鉴权后不会收到实时事件

[kernel/main.py:559](../../kernel/main.py:559) 只在进入循环前创建 `queue_task`；[kernel/main.py:584](../../kernel/main.py:584) 的 `auth` 分支只绑定 subscriber，没有创建队列读取任务。首帧鉴权客户端最多收到回放，之后的实时事件和终态不会推送。

### P1：内部事件总线没有接入任务 WS 事件流

`MCPHost` 在 [kernel/mcp.py:496](../../kernel/mcp.py:496) 和 [kernel/mcp.py:519](../../kernel/mcp.py:519) 发布 `mcp.tool.call/result`，但生产代码没有订阅总线并映射到 `TaskManager`。实测高危工具批准执行后的任务事件缺少 `tool.call` 和 `tool.result`，事件顺序及 UI 状态迁移不完整。

### P1：确认令牌过期不会自动超时收敛

[kernel/tasks.py:126](../../kernel/tasks.py:126) 无限等待确认 Future；确认管理器只在调用 `resolve` 时检查 TTL。令牌过期后任务会永久停在 `pending_confirmation`，不会产生 `resolved_by=timeout` 或终态事件。

### P1：工具执行的非 `MCPError` 异常会让任务永久保持 `running`

[kernel/tasks.py:133](../../kernel/tasks.py:133) 只捕获 `MCPError`。host 抛出其他异常时，后台任务异常结束，但任务没有 `task.failed`，状态仍是 `running`。

### P1：幂等键未绑定请求体

[kernel/main.py:227](../../kernel/main.py:227) 的缓存键只有方法、路径和 `Idempotency-Key`。同一会话用同一个键提交不同内容时，后一次请求会错误复用第一次的 task_id；缓存也没有过期或容量限制。

### P2：事件摘要的脱敏只检查字段名

[kernel/mcp.py:402](../../kernel/mcp.py:402) 仅对包含 `token/secret/password` 等关键词的键脱敏，任意字段值中的 API key、密码或完整返回内容仍可能进入 `args_summary` 或 `content_preview`。
