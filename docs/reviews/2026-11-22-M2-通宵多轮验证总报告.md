## 三、静态扫描对抗收敛（本轮重点）
已覆盖并实测拒绝的绕过面：
1. 直接危险调用（os.system/subprocess.run/eval/exec/ctypes）
2. import 别名（import subprocess as sp）、from-import（from os import system）、as 重命名
3. getattr 常量危险属性、__import__、importlib.import_module
4. **任意命名空间尾名**（from builtins import eval / import builtins as b; b.eval）
5. **下标动态取值**（vars(os)['system'] / os.__dict__['system'] / globals()['os'] / __builtins__['__import__']）
6. **赋值别名**（g=getattr; g(os,'system') / f=os.system; f() / e=eval）
7. **嵌套调用**（getattr(os,'sys'+'tem')(...) 动态拼接）
8. **容器存危险 callable**（d={'k':os.system} / l=[os.system]）
9. **类属性**（class A: m=os.system）
10. **实参传递**（functools.partial(os.system,...) / map(os.system,...)）
11. **编码混淆**（latin-1 coding cookie）、**语法混淆**（null 字节 → 拒绝而非静默跳过）
12. **原生/脚本入口**（.exe/.dll/.so/.bat/.ps1/.sh 等不可静态验证 → 拒绝）
13. **实例属性存入危险 callable**（a.m = os.system）
14. JS 入口危险调用（child_process/execSync/eval/new Function/spawn）

**定性（写入结项说明）**：静态扫描是**审查辅助**，不是安全边界。真正边界是签名信任 + 沙箱运行时策略。残余理论面（多层 a.b.c 属性链、lambda.__globals__ 复杂链、JS 正则混淆、反射构造）登记 M3 改 AST 污点分析或禁动态调用。

## 九、七/八轮：策略转向引用级兜底（最终态 265）

**七轮**（v7-gates 确认基线 + v7-bypass 独立 8/8 全拒 + DSH 自测发现 7 新绕过）：
方法/函数返回 os.system、operator.attrgetter、type() 动态类、星号解包、字典解包、iter/next —— 数据流传递路径无法穷举。
→ **通用兜底**：危险属性/内建/字符串只要被**引用**（不限调用点）即标记 exec_danger。

**八轮**（v7-bypass 指出 3 个 chr() 动态构造名绕过）：
os.__dict__[chr(115)+...] / os.__getattribute__(chr...) / vars(os).get(chr...) —— 动态构造名静态不可判定。
→ **反射内省封锁**：__getattribute__/__dict__/__globals__/__builtins__/__class__/__base__/__subclasses__ 属性 + vars/globals/locals/dir/chr/compile/setattr/delattr 内建一律拒绝。

**策略定性（重要）**：静态扫描从「黑名单穷举调用点」转为**宁严勿漏的引用级拦截**。代价是可能误伤极少数合法反射用法——已加 benign 插件回归验证官方工具与普通插件不受影响。真正的安全边界仍是**签名信任 + 沙箱运行时策略**；扫描定位为安装前审查辅助。
