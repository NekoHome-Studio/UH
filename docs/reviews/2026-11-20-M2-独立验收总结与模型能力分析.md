## 一、验收总结

### 1.1 三家 verdict：均不通过（MS-3 不结项）
| 模型 | 结论 | 核心阻断 |
|---|---|---|
| Claude-Sonnet-4.5 | 不通过 | P0 服务器仍 M1 部署，跨机链路无法验收 |

### 1.2 P0 阻断（三家共识，DSH 部署疏漏）
**服务器停留在 M1 部署**：M2 五模块（plugins/sandbox/hooks/themes/plugin_sdk）服务器不存在；cli/main/protocol/tasks 四核心文件版本落后；服务器测试集仅 148（缺 7 个 M2 测试文件）；POST /api/v1/plugins→405/空、GET /api/v1/themes→404、CLI 无 plugin 子命令。
- 「服务器 195/195」声明不实（DSH 提交 M2 后未 scp 部署到服务器）。
- 跨机插件 install/activate/主题/钩子链路全部无法验收。
- **处置：立即 scp M2 全模块 + 更新核心文件 + 测试集到服务器，重启，复跑 195 + 跨机链路。**

### 1.3 功能缺口（结项待补）
- **M2-1 生产调用闭环**：tasks.py 只走 retrieval_host，无 plugin registry 查找已安装工具→生产能力目录调用不通。
- **M2-1 启动重激活**：main.py startup 仅 register_capabilities(retrieval_host)，未遍历 registry 重激活已安装插件/Hook。
- **M2-2 沙箱审计**：SBX-01/02 拒绝无审计落盘，MCP 返回不含 UH-KRN-2010 错误码。
- **M2-2 出网静态扫描**：uh plugin validate 对含 socket/os.system/subprocess 的包返回 validated（静态扫描缺失）。
- **M2-3 生产态工具运行**：签名工具子进程无法导入 kernel 立即崩溃→quarantined（DeepSeek）；SDK 文档缺 manifest 模板/字段表/--no-verify 配置/打包签名步骤（Claude F-6/Hunyuan）；无 uh plugin pack/sign 子命令。
- **M2-6 安装来源**：受信 Git 实跑 + 目录/市场/Git 端到端安装 + 静态扫描拒绝证据缺。
- **SBX 平台矩阵**：Linux/macOS SBX-01~05 无运行环境证据；Win SBX-04 内存限额 DeepSeek 实测通过（32MB OOM kill）但 Hunyuan 未见证据（口径差）。

### 1.4 测试卫生
- **flaky 崩溃测试**（Hunyuan 确定性复现）：test_plugin_crashes_restart_three_times_then_quarantine——main.py sleep(0.05)，测试 await sleep(1.5) 断言 crash_count>=3，实测只 2 次（重启循环~0.5s/次，1.5s 容 2 次）。时间敏感设计缺陷，需放宽窗口或确定性触发。

### 1.5 通过项（本机口径，扎实）
- M2-4 主题：三家一致通过——切换 <200ms（Claude 9~25ms / DeepSeek 26~49ms / Hunyuan 12~18ms），JS 注入矩阵全拒，非法资产拒，刷新/重建恢复，DeepSeek 真实 WOFF2 渲染验证。
- M2-5 钩子：异常隔离 + trace/span 对照 + 卸载清理 + 超时回收。
- 安全专项：签名/篡改/不受信密钥拒装（SBX-06），沙箱越权 KRN-2010，secret 扫描无明文。
- SDK 上手计时：DeepSeek 39.1s / Hunyuan 28s / Claude 11s（但 Claude 诚实标注已知内核不具代表性 + 文档断链）。

### 1.6 诚实结论
M2 插件代码本机证据扎实（主题/钩子/签名/沙箱拦截），但**服务器未部署 M2（P0，DSH 疏漏）+ 生产调用闭环/重激活/沙箱审计/静态扫描/SDK 文档缺口**，MS-3 不能结项。须先部署 M2 + 补功能缺口 + 治 flaky + 跨机复验。
