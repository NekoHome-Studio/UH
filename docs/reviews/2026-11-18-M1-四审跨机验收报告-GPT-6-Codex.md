## 新发现

### P1：跨机验收资产和环境状态文档硬编码服务器鉴权 token

服务器 token 以明文出现在 [docs/runbooks/环境状态总览.md:55](../../docs/runbooks/环境状态总览.md:55)、`.work/probe-accept-cross.py:5` 和 `.work/probe-ws-cross.py:4`。即使 `.work` 被 gitignore，token 仍会进入工作区脚本、快照和可能的备份；环境总览属于仓库文档。该做法违反密钥必须经环境变量/钥匙串引用的项目规则，并且 token 还通过 query 参数进入跨机 URL。报告不回显 token 值。

### P1：跨机功能通过，但工具事件的 span 溯源仍未闭合

本机运行时探针显示 `mcp.tool.call` 和 `mcp.tool.result` 的内部 bus `span_id` 为空，外部事件得到不同的新 span；[kernel/tasks.py:64](../../kernel/tasks.py:64) 虽然尝试传递 `env.span_id`，但 [kernel/mcp.py:526](../../kernel/mcp.py:530) 发布 call 时没有生成 span，普通 result 路径也没有复用 call span。确认审计仍由 [kernel/confirmation.py:154](../../kernel/confirmation.py:166) 写内存列表和日志，没有带内部 bus/event/span 的审计事件。跨机功能探针不会覆盖这条审计反查链，因此 18/18 不能证明 M1-9 溯源验收通过。

### P2：服务器状态采集脚本的 kernel version 检查失败

远程执行 `D:\uh\server-state.ps1` 时，`kernel version` 步骤报 Python `unicodeescape` SyntaxError，原因是脚本把 `D:\uh` 放进 Python `-c` 的普通字符串，触发 `\u` 转义。其余端口、进程、venv 版本采集仍返回；该脚本不能完整作为生产状态快照。
