## 需求
### 1. OTel SDK 接入（可选依赖，默认关闭）
- `kernel/otel.py`：**未装 OTel 包或未设 `OTEL_EXPORTER_OTLP_ENDPOINT` 时为 no-op**，零额外开销（验收明确要求）。
- 生产设 endpoint 后启用 OTLP 导出（gRPC/HTTP 按 env），Resource 带 service.name=uh-kernel / service.version。
- **本地开发默认关闭**；提供 `UH_OTEL_ENABLED` 显式开关与 endpoint 双重判定。

### 2. trace_id 关联（关键验收：span 层级与 trace_id 关联正确）
- 现有 `uh_trc_<32hex>` 与 OTel 128-bit trace_id **必须可互映射**：建议取 hex 部分作为 OTel trace_id，使 Jaeger 中看到的 trace 与日志/信封 trace_id 一致（去掉前缀即可对齐）。
- span 层级：请求 root span → 路由/能力调用子 span → MCP 工具调用孙 span；**parent_span_id 与 Envelope 字段打通**。
- 跨服务传播：W3C `traceparent` header 注入出站请求（能力模块 RPC / MCP），入站解析续接。

### 3. span 命名对齐 §7.6.2
- 从上游提取命名规则并实装；报告列出你提取到的规范与实际 span 名清单。
- **attribute 基数纪律**（同 M3-3）：禁 session_id/task_id/user_id 等高基数属性作为**索引维度**；trace_id 可作 attribute（本身是 trace 标识不是聚合维度），但路由须模板化。

### 4. 采样策略（Issue 风险点，必须明确）
- 默认 `parentbased_traceidratio`，比率经 `UH_OTEL_SAMPLE_RATIO`（默认 1.0 开发 / 生产建议 0.1，文档写明）。
- **错误请求强制采样**（tail-based 或 always_on 错误分支），避免采样偏差漏掉故障链路——这是风险项的核心。
- 文档说明采样对指标/告警的影响（指标是全量计数，不受采样影响）。
